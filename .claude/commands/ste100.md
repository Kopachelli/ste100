description: Check or rewrite text against ASD-STE100 Simplified Technical English. Classifies the text type, runs the structural checker, reports every finding with its rule number, and rewrites on request. Never claims dictionary compliance.
argument-hint: <file, glob, or pasted text> [--audit|--rewrite] [--type procedure|description|safety|note|machine] [--glossary FILE]
allowed-tools: Read, Write, Edit, Glob, Grep, Bash(python:*), Skill

Apply **ASD-STE100 Simplified Technical English** (Issue 9) to: **$ARGUMENTS**

Load the `ste100` skill for the rules. If it is not available, read
`skills/ste100/SKILL.md` and its `references/` directly. Do not work from memory
of the standard.

## Parse the request

| Argument | Meaning | Default |
|---|---|---|
| A path or glob | Check those files | — |
| No path | Use the text in the message, or the current selection | — |
| `--audit` | Report findings, change nothing | Default when the target is a file you did not just write |
| `--rewrite` | Return the rewritten text | Default for pasted text |
| `--type X` | Force the text type | `auto`, classified per block |
| `--glossary FILE` | Project terminology | `.ste100/glossary.json` if it exists |

## Step 1 — Classify

STE applies different rules and different limits to different kinds of text.
Getting this wrong is worse than doing nothing.

| Type | Limit | Verb form |
|---|---|---|
| Procedure | 20 words (5.1) | Imperative (5.3) |
| Description | 25 words (6.3) | No imperative |
| Safety instruction | 20 words (5.1) | Command or condition first (7.2) |
| Note | 25 words (5.5) | Information only (5.5) |
| Machine-facing string | 25 words | Follow the sense of the string |

Classify **each block**, not the whole document. A real document mixes types.

## Step 2 — Run the checker

```bash
python skills/ste100/scripts/ste_check.py --type auto [--glossary FILE] TARGET
```

If the skill is installed but this repository is not the working directory, use
`~/.claude/skills/ste100/scripts/ste_check.py`.

Run it. Do not count words by hand — section 8 of the standard defines what a
word is, and the count differs from a plain word count in both directions.

`VIOLATION` findings are certain. `review` findings are heuristic and need your
judgment; say which ones you accepted and which you dismissed, and why.

## Step 3 — Add what the checker cannot see

Read for these and report them alongside the tool's findings:

- **6.1** information given gradually, one subject per sentence
- **6.2** key words repeated to connect sentences, not rotated for variety
- **6.4, 6.5** each paragraph opens with its topic sentence and holds one topic
- **7.1** warning for a risk of injury or death, caution for damage to objects —
  a risk analysis, which no tool can do
- **9.1** rebuild the sentence when no word-for-word replacement works
- **1.9, 1.11** technical nouns short, well known, and the same every time

## Step 4 — Output

**Audit** — a table, most severe first:

```markdown
| Rule | Type | Line | Finding | Fix |
|---|---|---|---|---|
| 3.2 | procedure | 14 | "has completed" is present perfect | "is complete" |
| 2.1 | description | 22 | 5-word multi-word noun | use prepositions |
```

Then: how many violations, how many review items, and one line naming the rules
that were **not** checked.

**Rewrite** — the rewritten text and nothing else. No preamble, no mode
announcement, no violation count, no closing offer. One permitted addition: a
single line beginning `Kept as-is:` when you deliberately kept a longer phrasing,
naming the phrase and the precision a shorter one would have lost.

If the text already obeys the rules, say so. Do not invent changes.

## Non-negotiable

- **Never claim "STE compliant".** Rules 1.1 thru 1.4, 1.6 and 9.2 need the
  approved dictionary, which this project does not have. Say **STE-informed**,
  and say that word choice was not verified.
- **Never turn a hedge into a fact.** "The request may have failed" is not "The
  request failed." When rule 3.2 and modality conflict, keep the hedge and flag
  the departure.
- **Never add a fact the source did not state**, and never drop a safety
  condition, limit, or scope qualifier to get under a word count. Keep the longer
  text and report the conflict.
- **Never quote ASD's dictionary or rule text.** Cite the rule number.

## When the job is bigger than this command

If the request is open-ended — "make our documentation STE", "audit this repo" —
this command is the wrong tool. Say so and hand off to the `ste100` agent, which
scopes the work, asks what it needs to know, and remembers the answers.
